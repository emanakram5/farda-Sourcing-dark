FARDA SOURCING - DEPLOYMENT PREREQUISITES
Updated: 24 November 2026
Source branch: redesign/reference-website
Repository: https://github.com/emanakram5/farda-Sourcing-dark
Canonical website: https://fardasourcing.com

1. BUILD AND ARTIFACT
This is a static React/Vite website. Node and npm are required on the build
machine, not on a server serving prebuilt files. The contact API requires a persistent Node.js service; there is no database.
The local build was exercised with Node v26.13.0 and npm 11.20.0. Choose and
pin a supported Node release compatible with the lockfile in deployment CI;
validate the build there before launch rather than assuming another version.

From the approved checkout:
  npm ci --include=dev --no-audit --no-fund
  npm run build

Use npm.cmd on Windows if PowerShell blocks npm.ps1. Include development
dependencies during installation because Vite is needed for building.
Publish the CONTENTS of dist/, including nested route directories, assets,
images, sitemap.xml and robots.txt. Keep the exact commit and toolchain in the
release record. Do not publish source, .git, node_modules, credentials or logs.
Use a static host/web server for production; dev/preview are local tools.

2. ACCESS AND DOMAIN
Prepare hosting/server access, DNS control, an approved release and rollback
artifact. Configure HTTPS for fardasourcing.com with certificate renewal and
redirect the alternate www/HTTP addresses to the canonical HTTPS address.
Confirm domain ownership, DNS, hosting and certificates before launch; these
have not been configured or verified by the local source changes.
If the production domain changes, update SITE_URL in
src/data/productDetails.js and rebuild all metadata and the sitemap.

3. ROUTING - GENERATED HTML BEFORE SPA FALLBACK
Serve existing files and generated route/index.html before the SPA fallback.
This is essential for product-specific titles, descriptions and canonical tags.
Vercel: the checked-in vercel.json supplies route rewrites and the old
/how-it-works redirect. Build command: npm run build. Output directory: dist.
Netlify: public/_redirects supplies a final SPA fallback; preserve normal
existing-file shadowing and configure /how-it-works -> /home as a redirect.
Other servers must implement equivalent rules. Example Nginx location rules:

  location = /how-it-works { return 301 /home; }
  location /assets/ { try_files $uri =404; }
  location /images/ { try_files $uri =404; }
  location / { try_files $uri $uri/index.html $uri/ /index.html; }

Review/adapt this snippet to the actual server and document root. Do not route
missing JavaScript, CSS or images to index.html. Use appropriate MIME types.
Client-side unknown routes show a 404 view; the generic SPA fallback may still
respond HTTP 200. Configure a real server 404 strategy if that is required.

4. SEO AND STATIC FILES
The build creates HTML for regular routes and all six /products/:slug URLs,
with unique titles/descriptions, canonical tags, social metadata and product
structured metadata. Product HTML also includes a no-JavaScript text fallback.
The generated sitemap lists canonical routes and excludes aliases; robots.txt
references https://fardasourcing.com/sitemap.xml. Ensure both are publicly
accessible after deployment, then submit the sitemap to the chosen search
console. Generation does not guarantee search indexing or rich results.
Keep all public/images files referenced by the source. The four uploaded JPGs
are about 1.6-1.9 MB each; consider derived compressed/responsive assets if page
weight needs improvement, retaining the originals and visual quality.

5. CONTACT AND EXTERNAL RESOURCES
The Contact Us page posts to /api/contact. Run server/contact.mjs on loopback
port 3001 behind the same HTTPS host, with the proxy and private SMTP settings
described in server/README.md. Use .env.example as a template. SMTP is not
configured yet; delivery is pending setup and a real inbox test. Never expose
SMTP credentials in dist or VITE_ variables. Static hosting alone cannot run
the API. The previous Vercel rules cover the site, not this Node service.
There is no active newsletter integration. No API secrets belong in Vite's
public client bundle. Review contact/social details before launch.
The Inter font is loaded from Google Fonts with system-font fallbacks; verify
production access or self-host if required.

6. RELEASE CHECKS
- Build the exact approved source successfully and retain the prior artifact.
- Verify HTTPS, canonical redirects and direct refreshes on all main routes.
- Open all six product URLs directly; inspect metadata without relying on JS.
- Verify sitemap.xml, robots.txt, image requests and missing-asset 404s.
- Check phone/tablet/laptop/desktop and short landscape, overflow and text.
- Test full product card clicks, cross/Escape dismissal and focus restoration.
- Test mobile navigation, reduced motion, final counter values, inquiry presets
  and validation; confirm actual inbox receipt after configuring SMTP.
- Cache hashed assets long-term; revalidate HTML and unversioned assets.
- Upload the entire release before switching traffic; confirm rollback access.

This file describes prerequisites. It does not deploy or publish the website.
